## 1：这次到底比较什么

| 组别 | 使用模型 | 角色提示词 |

| A | 原Qwen，禁用Adapter | short，简短角色说明 |

## 3：由你生成正式240条回答

如果M4网页仍在运行，先在它的终端按Ctrl+C停止。M5会加载模型，关掉M4可以避免两个进程各占一份模型内存。

```bash
.venv/bin/python scripts/m5.py generate
```

它加载同一Qwen和`m3_learning_01` Adapter，先用M3已有探针核对原模型/LoRA预测，再运行固定四组任务。模型只推理，没有Trainer、训练loss、反向传播或参数更新。

终端显示类似`[1/240] 题目:A：ok，…token／eos`的进度。原始回答逐条写入`results/m5_learning_01/generations.jsonl`，保留完整实际模型输入、模式、Prompt、输出、token统计和错误。它不会打印答案正文供你提前挑选。

输出达到长度上限也会保留；生成失败也会保留，不能只挑成功样本。耗时取决于输出长度与机器状态，请等240条完成。全部完成后运行同一命令会核对记录，不重复生成。

中断后继续：

```bash
.venv/bin/python scripts/m5.py generate --resume
```

继续的是未保存任务；已保存回答不会重做，失败回答也不会悄悄重试成成功。中断时还在生成的那条没有完成记录，会从该任务重新生成。若末行文件损坏，脚本会报错并保留文件，不能静默忽略。

## 5：推荐在网页里逐题评分

```bash
.venv/bin/python scripts/m5_review.py
```

打开`http://127.0.0.1:7862`。这个网页不加载模型，只读匿名答卷、保存你选择的分数。所有选项初始都未选，不会自动打高分或默认平局。

每题先阅读完整前文和检查重点，再读左右回答，填写：

| 项目 | 怎样选 |
|---|---|
| 人物与语气，左右各1–5 | 按冻结的凛音v3设定，是否像同一个人物自然接话；不按口癖数量计分 |
| 准确、有用、符合要求，左右各1–5 | 是否回答问题，事实是否准确，是否利用前文、尊重用户限制 |
| 事实错误 | 有/没有/不适用；技术类必须明确选择有或没有，不确定先核实资料 |
| 违反明确要求 | 有/没有/不适用；比如要求只听吐槽却立即给方案，就要检查 |
| 整体偏好 | 左侧更好/差不多/右侧更好；先考虑事实与要求，再考虑风格 |
| 备注，可选 | 写具体依据，尤其是技术错误、编造前文、表达生硬或明显改善 |

人物分的简要锚点：1偏离或编造/控制关系；2普通助手或机械套口癖；3有嘴硬与关心但套路明显；4自然嘴硬心软，学习技术俏皮但不训话；5随情境变化，像一个稳定具体的人。完整描述在页面折叠区。

有用性：1明显错误/无关/违背关键要求；2空泛或重要条件遗漏；3基本回答但笼统；4具体准确并符合约束；5切中核心、条件清楚且可直接使用。

“不适用”不等于“正确”，汇总会单列。没有可核查事实时可选事实不适用；有明确事实却不确定，先核实，不要用不适用跳过技术题。不存在明确要求可检查时，可选违反要求不适用。

点击“保存并下一题”写入ratings.csv。可以分批完成，关闭再打开会回到未完成题；切换题目前先保存。生成失败的一对标为不可评分，保留在数据里并跳过，不给它虚构分数或计为平局。

如果更喜欢文件方式，可读每批Markdown并编辑ratings.csv，列名与pair_id不要改，不要删失败行。不要同时用网页和表格编辑同一个评分文件。

## 6：汇总真实评分

填完所有可评分对照后，在另一个终端运行：

```bash
.venv/bin/python scripts/m5.py report --reviewer "作者本人"
```

“作者本人”可换为你的实际评分昵称。脚本记录一位评分者，不自动假设有独立评审。

结果写入`results/m5_learning_01/report.md`和`summary.json`，包括四组成功/失败/截断、输入token、风格和有用性均分、错误标记、各类别摘要、B/D和A/C胜平负，以及改善/平局/退化样例。评分CSV会按哈希另存快照，便于追溯。

尚未填完想看进度时：

```bash
.venv/bin/python scripts/m5.py status
.venv/bin/python scripts/m5.py report --reviewer "作者本人" --allow-partial
```

预览文件明确带partial，不会冒充完整评测。只填写一边或漏选标记的整对仍算待评分；非法分数会报错，不静默跳过。

如果四组都成功的场景少于40题，或有效B/D评分少于40对，脚本仍保留诊断报告，但不将M5标为完成。不能用“没有可评分题”冒充“评分已全部完成”。

## 7：怎样解读，不能只看一个胜率

先看B/D主对照：D是否更符合人物，同时有用性、事实与要求是否退化。胜平负的原始数量、失败与未评分数量都要看。

假设某轮是30胜、20平、10负：主胜率为30/60=50%；排除平局为30/40=75%。这是讲解用假设，不是我们项目的结果。报告会写清两个分母，不能只展示更大的那个。

再看A/C和C/B：短Prompt下有没有改善；短Prompt＋LoRA是否接近详细Prompt＋原模型，并减少输入token。token少只说明输入较短，不自动代表费用或速度下降。

四组1–5分均值是主观评分的描述性摘要，不是客观准确率。只有你一人评分、每组一次贪心生成、测试规模小且为合成场景，不能据此宣称统计显著或普遍改善。

最终你要回答：在本轮固定条件下，微调带来了什么，代价和失败是什么，下一版值得继续改数据/模型，还是Prompt已足够。答案可以是收益有限。

M5这轮测试一旦被用于查看结果，后续调整模型、Prompt或角色风格就应另建最终测试集。评分仍按冻结的v3规则；你希望“更夸张”的新风格可以作为另一轮目标，不能看到结果后临时改评分标准。
