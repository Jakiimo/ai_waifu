# M4：把训练好的模型接成聊天 Demo

本阶段加载你亲手完成的 `m3_learning_01`。代码、依赖和开发检查由助手准备；下面的终端命令、网页体验与人工验收由你执行。M4只有推理，没有训练，也不改A/B参数。

## 1：先知道输入和输出

`reply()` 的输入是本次用户文字、当前会话历史和模型模式。输出包括实际回复，以及加入本次问答后的新历史。

```text
文字＋对话历史
→ 加入system角色提示词
→ Tokenizer转成token编号
→ Qwen＋已训练LoRA生成新token
→ 解码为回复文字
→ 把本次问答加入历史，交给网页显示
```

Gradio只负责输入框、聊天记录、按钮和调用Python函数。模型计算在你的电脑上由PyTorch、Transformers和PEFT执行。启动网页不会重新训练。

## 4：读懂这三处代码

阅读 `demo.py`，按 `ChatEngine.ensure_loaded` → `ChatEngine.reply` → `ChatEngine._generate` 的顺序。

### 加载结果：ensure_loaded

```python
base, tokenizer, device = load_base(self.train_cfg)
model = PeftModel.from_pretrained(
    base, self.adapter, is_trainable=False, local_files_only=True
)
model.eval()
```

`load_base`加载原Qwen。`PeftModel.from_pretrained`读取训练后的A/B，加入基础模型；`is_trainable=False`用于推理，脚本进一步检查所有参数都不允许训练。

`model.eval()`切到评估模式，例如关闭训练时的dropout。它本身不等于关闭梯度，后面用`torch.inference_mode()`关闭推理过程的梯度记录。

### 整理输入：reply

```python
messages, kept, dropped, _ = prepare_messages(...)
result = self._generate(messages, mode)
```

这里的messages包含固定system、历史完整问答、本次user消息。没有本次assistant的参考答案，也没有labels。生成完成后，才把真实回复加入历史。

例子：先说“小猫叫薄荷”，再问“它叫什么”。第二次输入会包含上一轮的用户消息与模型回复。模型借助重新发送的前文回答；没有实现跨会话长期记忆。

### 执行生成：_generate

```python
ids = tokenizer.apply_chat_template(
    messages, tokenize=True, add_generation_prompt=True,
    return_tensors='pt'
).to(device)

with context, torch.inference_mode():
    output = model.generate(...)

new_tokens = output[0, ids.shape[1]:]
answer = tokenizer.decode(new_tokens, skip_special_tokens=True)
```

`add_generation_prompt=True`加入“接下来由assistant回复”的格式标记，不提供答案。`generate`根据输入逐步生成后续token。它返回输入加新token，因此切掉原输入，只解码新生成的部分。

原模型模式的context是`model.disable_adapter()`，微调模式正常启用Adapter。两种模式共用一份基础模型；同题比较时先运行原模型，再运行LoRA，以减少驻留内存。锁和Gradio串行队列防止生成中途被其他请求切换Adapter。

## 5：启动网页

助手准备界面时安装了兼容的Gradio。若换环境，需要安装：

```bash
.venv/bin/python -m pip install -r requirements-m4.txt
```

原训练环境的所有依赖由`requirements-lock.txt`约束，新增界面依赖使用Gradio 6.0.2。新版Gradio要求不同的Hugging Face依赖，本项目没有为此升级原训练环境。

启动：

```bash
.venv/bin/python demo.py
```

保持终端运行，在浏览器打开 `http://127.0.0.1:7860`。默认仅本机访问，没有开启公开分享。按Ctrl+C停止服务，模型文件和实验记录仍保留。

首次发送时才加载模型，网页会提示正在加载或生成。后续对话复用内存中的同一份模型。网页中每个会话独立保存历史，不把聊天内容自动写入训练集或磁盘。

## 6：按顺序体验

1. 在“聊天”页发送一句话，等待实际回复，观察生成状态和按钮恢复。
2. 说“小猫叫薄荷”，再问“刚才小猫叫什么”，检查当前会话是否带上前文。是否答对属于模型质量，代码会保留并发送前文。
3. 点击“新会话”，再问同样的问题。新会话的模型输入不包含前文，不应把模型偶然猜中当作长期记忆。
4. 切换原模型/微调模型。聊天记录会清空，当前模式仍显示在页面上。
5. 在“同题比较”页输入同一问题。两边使用冻结的详细Prompt与相同贪心解码、生成上限，比较区域不读取聊天历史。这是带模型标签的体验，不是M5盲评。

## 7：上下文与错误怎样处理

输入上限为768 token，生成上限256 token。对话过长时按完整问答轮次移除最早历史，保留system和当前问题，并在网页说明移除了几轮。如果当前问题单独就放不下，程序报可理解的错误，要求缩短；不会截断后假装完整回答。

达到生成长度上限时，界面提示这条回复可能未说完。推理失败时原历史保留，按钮恢复，可以重试或开始新会话。技术错误、人设偏离等属于已有模型质量限制，网页不能自动修好。

只要依赖已安装，先运行`--check`排查模型产物；端口被其他程序占用时可在`configs/m4.json`修改server_port。不要改原训练配置来修改网页端口。
