# M2：为凛音准备数据与对照实验

当前版本 `m2-tsundere-v3`；30条抽查全部pass，准备包已冻结。角色是嘴硬心软的傲娇型，具体设定见 [角色卡](凛音_角色卡.md)。旧版游戏比喻式数据已归档，当前入口统一使用傲娇版。

## 1 这一阶段做什么

M1 证明了电脑能加载模型、训练小 Adapter、保存并重新加载。M2 先确定“希望模型怎样说话”和“怎样检验它”，还没有正式训练这个角色。

我们准备三类材料：

| 材料 | 当前数量 | 用途 |
|---|---:|---|
| 训练集 | 360 条／120 个场景族 | M3 用它更新 LoRA 参数 |
| 开发集 | 24 个场景 | 现在比较和调整提示词，以后检查训练效果 |
| 测试集 | 60 个场景 | M5 最终比较；目前没有生成模型回答 |

一个训练场景族有三种问法，使用同一个目标回复。因此 360 条不等于 360 个独立场景，也不意味着拥有 360 种回答；当前有 120 个不同目标回复。

训练集含 300 条单轮样本、60 条带前文样本。日常、安慰、学习、技术各 75 条，关系情境 60 条。后者让模型接触“被夸、被逗、明确拒绝建议”等触发条件，避免每句话都机械加“才不是”。

## 2 先看两个文件，分清“我们写的”和“模型说的”

- [30 条台词抽查](../results/m2/review_samples.md)：我们原创的训练目标。相当于希望模型模仿的示范答案，不是模型已经学会的证据。
- [开发集对照](../results/m2/prompt_comparison.md)：未经本项目正式微调的 Qwen 模型，收到三种提示词后实际生成的回答，原样保存。

对照页里的 `short` 是简短角色指令，`strong_profile` 是详细设定，`strong_examples` 在详细设定后增加四个训练区示例。示例没有从开发或测试的参考答案中选取。三个版本都没有附加旧版只给长提示词的技术背景知识。

完整开发集有 24 题；这次只抽其中固定的 9 题比较三种提示词，总计 27 个输出。它是小规模开发检查，不是全部开发题评测，更不是最终盲评。

## 3 30 条表怎么用

打开 [CSV](../results/m2/review_samples.csv)。每条包含类别、前文、当前问题和凛音的目标回复；每个场景族只抽一条，共 30 个不同场景族。

在 `human_verdict` 列填写：

- `pass`：这句话适合作为训练示范。
- `revise`：保留场景，但台词需要修改；在 `notes` 写具体问题和建议。
- `reject`：这个样本不适合训练；在 `notes` 写原因。

重点检查：是否真的在接前文；嘴硬是否有变化；关心有没有具体表现；用户难受时是否仍在挖苦；技术解释是否正确。不要按“哼”“才不是”出现几次打分。

当前30条示范已由用户明确确认全部pass，审核汇总为30/30、pending=0。此前12条修改意见和已完成的改写仍分别保存在 `previous_verdict` 与 `revision_status`，不会抹去过程记录。训练主数据有360条，抽查通过不等于全量逐条审核，也不等于开发集的模型回答通过。

这一步已完成，你不需要继续填写或替换台词。现在从第5节按命令复跑、理解数据和loss范围即可。若将来要改冻结数据或Prompt，建立下一版实验，不覆盖当前记录。


## 4 数据怎样变成模型输入

原始材料在 [raw_cards.jsonl](../data/m2/raw_cards.jsonl)。一个场景包含 `user_variants`（三种当前问法）、`assistant`（目标答案），多轮场景还有 `history`（前文）。

[prepare_data.py](../prepare_data.py) 展开后写到 [train.jsonl](../data/m2/train.jsonl)。它不会丢掉 `history`，而是把前文、当前问题、目标答案顺序拼起来。去重也使用完整前文加当前问题：同一句“你怎么看”，在不同前文下不一定是同一条样本。

例子中的结构是：

```text
system：凛音的简短角色指令
user：谢谢你刚才陪我看报错。
assistant：错误找到了就好。
user：你其实很关心我嘛。
assistant：谁、谁很关心你了……（本条目标回复）
```

Tokenizer 将这些文字和聊天模板转成 token 编号。输入会保留整个对话，模型看得到前文。

[training_data.py](../training_data.py) 只让最后一句 assistant 和它的结束标记参与 loss；system、之前的 user/assistant、当前问题和 padding 的 `labels` 都设为 `-100`。这表示它们提供上下文，但不要求模型在本条训练样本里把前文重新背出来。

`attention_mask` 表示哪些输入位置是有效内容；`labels` 表示哪些位置要评分。前文通常是 `attention_mask=1`、`labels=-100`，两者作用不同。

当前每条最大长度为 256 token，不足的补 padding。超长样本直接报错，不偷偷截掉目标答案。这批数据实际最长 152 token。

| 命令 | 作用 | 当前预期 |
|---|---|---|
| prepare_data.py | 整理数据；冻结后核对文件指纹 | “M2已冻结，文件校验通过”；不覆盖数据 |

| status | 查看本轮实验是否齐备 | 360条训练、24开发、60测试；27条开发输出；30条通过、待复读0；已冻结 |

我已完成本轮实际准备和推理，所以你复跑时主要是在检验和理解已有结果；缓存消息是正常的，不需要删除结果去强行重新生成。

每步跑完先看输出，再打开对应文件：原始场景 `data/m2/raw_cards.jsonl`、展开结果 `data/m2/train.jsonl`、检查报告 `results/m2/data_report.json`、模型回答 `results/m2/prompt_comparison.md`。先认识一族三个问法怎样展开，再看多轮前文如何保留。

如果想亲手观察“最后一句才参与loss”，下面这个练习会使用当前v3真实数据和Tokenizer重新计算一条样本，只读不保存，不加载GPU模型：

```bash
.venv/bin/python - <<'PYCODE'
from transformers import AutoTokenizer
from prepare_data import RAW, MODEL, CONFIG, PROMPTS, read_json, read_jsonl, expand_cards
from training_data import encode_conversation

rows, removed = expand_cards(read_jsonl(RAW))
row = next(r for r in rows if len(r["messages"]) > 2)
tokenizer = AutoTokenizer.from_pretrained(MODEL, local_files_only=True)
encoded, counts = encode_conversation(
    tokenizer, read_json(PROMPTS)["short"], row["messages"], read_json(CONFIG)["max_length"]
)
print("展开数量：", len(rows), "；移除：", len(removed))
print("样本：", row["id"])
for message in row["messages"]:
    print(message["role"] + "：", message["content"])
print("前文标签全为-100：", all(x == -100 for x in encoded["labels"][:counts["prompt_tokens"]]))
print("实际参与loss的文字：")
print(tokenizer.decode([x for x in encoded["labels"] if x != -100]))
print("token统计：", counts)
PYCODE
```

你应该看到360条展开实例、保留的多轮前文、前文标签检查为True，以及只有最后一条回复和结束标记被解码出来。前文能被模型读取，但不在这条样本中作为要复述的目标评分。

字符近重复检查只能发现部分文字重复，不证明所有语义泄漏已经排除。来源和数量口径见数据卡。

## 6 为什么先比较提示词

如果原模型靠详细提示词就能很好地扮演角色，微调的额外收益可能很小。先建立这个基线，后面才不会把“训练过”当成“变好了”。

开发推理命令：

```bash
.venv/bin/python scripts/m2.py dev-probe
```

脚本加载 M1 同一基础模型，使用 MPS、bfloat16、固定生成上限、贪心解码；不加载 M1 的 Adapter，也不更新参数。每道题的预置前文一致，只改变角色提示词。

当前对照已经实际生成并冻结；这条命令核对数据和证据后返回缓存，不覆盖回答。不同版本或被改动的证据会拒绝复用。直接阅读对照页和 [提示词选择说明](../results/m2/prompt_decision.md) 即可。

当前提示词已加入学习/技术时俏皮、带姐姐感的表达，示例来自训练区。“强提示词”只是本轮选定的详细基线，不保证最优，也不保证小模型每个技术问题都答对。尤其不能把我们写的参考答案换进去，伪装成模型输出。

## 7 冻结是什么意思

`data/m2/frozen_manifest.json` 保存配置、角色卡、数据、提示词、评分规则、关键代码与实验记录的 SHA-256 指纹。像给准备包拍一张可核对的快照：之后改文件，校验会提示不一致，不能拿旧结果冒充新实验。

代码会检查开发输出属于当前数据、评分规则和模型版本，所有候选提示词与指定场景都有回答。旧版同名路径里的文件不能直接复用。

本轮已选定 `strong_examples` 并完成工程冻结，30条示范的人工抽查通过。原模型在任务理解、技术事实和角色反差上仍有失败，记录全部保留。冻结是固定实验条件，方便后面公平比较，不要求原模型已经达到目标语气，也不是模型质量合格证明。

若复跑冻结命令：

```bash
.venv/bin/python scripts/m2.py freeze
```

会校验已有清单并返回“未覆盖”。你不用手工改 `ready_to_freeze` 或删除清单。


## 8 下一阶段学什么

M2准备包已经完成。学习完本章、能解释训练/开发/测试和最后回复的监督范围后，就可以进入M3。M3才会把这批数据接入 Trainer，用 PEFT 插入 LoRA，只更新适配参数。正式训练要使用这里同一个多轮编码函数，不能照搬 M1 只接收 `user`/`assistant` 的单轮教学入口。

最终四组是 A 原模型+短提示词、B 原模型+强提示词、C LoRA+短提示词、D LoRA+强提示词。主要比较 D/B，使用完全一致的提示词、前文和生成参数，检查 Adapter 是否带来额外变化；答案质量还要通过独立测试与人工评审判断。
