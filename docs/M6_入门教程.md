# M6：先生成偏好候选，再做DPO

本课是M6的第一步。学习者已完成前20题的40条真实候选，助手已审核并导出20组偏好：2组直接选用、18组明确修订chosen。学习者也已完成第二步的5次真实Qwen DPO更新与独立重载，当前继续[M6第三步](M6_第三步_扩展偏好数据.md)扩展候选。以下保留第一步操作说明。

## 1. 这次做什么、输入什么、输出什么

M3 SFT的数据是“问题＋一个示例回答”。M6要准备“同一个问题＋较好的回答chosen＋较差的回答rejected”。DPO随后用这对答案学习相对偏好，不是把一个1–5分数直接加到LoRA矩阵里。

当前这一步只负责生成候选：

```text
固定short系统提示词＋一个新问题／预置对话
       ↓ 当前Qwen＋已训练好的SFT LoRA，采样两次
候选一、候选二
       ↓ 助手核查事实、要求、人物语气并审核
chosen／rejected，或拒收／明确修订
```

采样时没有目标答案。审核重点expectation不交给Qwen；生成也不计算训练loss、不反向传播、不改A/B。与M5不同，M5用固定贪心输出评测，而这里用随机采样得到可能不同的候选。设定seed可追溯，但不能保证跨设备与版本完全一致。

## 3. 你现在亲手执行的命令

如果M4网页仍在运行，先在它的终端按Ctrl+C关闭，避免同时驻留两份模型。

```bash
cd "/Users/jakiimo/Desktop/AI Waifu"
.venv-m6/bin/python scripts/m6.py status
```

最初应看到场景计划180/30/60、train候选0/360、dev候选0/60、审核记录0；当前第一批完成后为train候选40/360、dev候选0/60、审核20。最大实际输入为123 token。status会创建或核对准备清单，只编码问题，不生成回复。

然后只跑第一批20个训练场景，每题两条，共40条真实候选：

```bash
.venv-m6/bin/python scripts/m6.py collect --split train --limit 20
```

`--limit 20`表示取训练集合前20题，不是20轮训练，也不是新增20题。问题按六类交错排列，小批次也会覆盖主要场景。命令首先加载基础模型与已有SFT Adapter，检查MPS/bfloat16与来源一致，然后逐条采样。终端显示候选key、成功/失败、eos或length；length表示达到128新token上限，不保证回答完整。

结果写入results/m6_preparation/candidates.jsonl。耗时取决于输出长度与机器状态，暂不承诺分钟数。重跑已完成小批次会核对并复用，不再次生成。

如果中断，运行：

```bash
.venv-m6/bin/python scripts/m6.py collect --split train --limit 20 --resume
```

只继续尚未保存的候选。已保存的生成失败不自动重试成成功；损坏JSON行会报错并保留文件。失败如何重新采样需另记尝试版本，不删除坏结果掩盖失败。

完成后创建阅读包：

```bash
.venv-m6/bin/python scripts/m6.py review-pack --split train
```

终端会打印具体JSON路径，对应同名Markdown可直接阅读。它显示新问题、预置前文、审核重点与随机左右回复，不会帮我们选赢家。包按内容哈希命名，后续扩展候选不会覆盖这批阅读材料。

## 5. 原理先掌握到这里

**为什么两条回答必须对应同一个输入？** 如果问题、前文或系统提示词不同，优劣可能来自输入变化，不能作为清晰的同题偏好。

**chosen/rejected在哪里起作用？** 在后续训练中，模型分别计算两条完整答案的token概率，得到回答的对数概率，再与冻结参考模型的对应概率比较。只有最后答案和结束符参与目标概率，问题与历史仍是输入，padding不参加。

**参考模型是谁？** 本阶段训练起点是“Qwen＋当前SFT LoRA”，参考就冻结这一整套预测行为。关闭LoRA变成裸Qwen不是同一个起点。以后会用两份小Adapter或等效参考概率缓存保持这个区别。

可选公式演示：

```bash
.venv-m6/bin/python scripts/m6_loss_demo.py
```

它不加载Qwen，只用虚构的chosen/rejected对数概率演示DPO公式和梯度方向。起点与参考相同时margin为0、loss约0.693147；这不表示模型两条答案等概率，只表示当前相对差与参考相同。演示打印的数不是实际模型回答的分数，也没有更新LoRA。

实际训练更新A/B参数，概率变化是参数更新后的结果；不会把chosen整段文字直接转换为一组A/B，也不会把冻结参考参数减去可训练参数得到新Adapter。公式、序列概率细节将在拿到真实偏好对后继续讲。

## 6. 源码阅读路线与回顾

主链：命令 → scripts/m6.py:main → prepare/preflight → collect → build_candidate_tasks → CandidateEngine.ensure_loaded/generate → generate_candidates逐条保存 → review_pack → 等待实际审核 → export_pairs。

必读顺序：

1. configs/m6.json：输入数据版本、两条候选、采样参数和长度上限。
2. preference_data.py:build_candidate_tasks：相同messages、不同seed，不传expectation。
3. scripts/m6.py:CandidateEngine.ensure_loaded：加载已有SFT，所有参数冻结，检查来源设备。
4. CandidateEngine.generate：文字→token→采样→去掉输入token→候选文字与结束原因。
5. generate_candidates：先核对缓存，再逐条append、flush/fsync；中断保留已保存结果。
6. review_pack与preference_data.py:validate_decision：匿名材料与真实审核分开，没有审核不导出偏好对。

选读tests/test_m6_preference.py与M6_验证记录.md，暂缓TRL训练器源码和PPO，当前还未进入正式训练。
