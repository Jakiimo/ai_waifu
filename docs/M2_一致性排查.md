# M2 傲娇版一致性排查

历史排查及当前v3更新，日期：2026年10月13日。用户指出开发集对照仍像旧版，检查确认是主流程没有切换，不是仅仅页面缓存。

## 原因

上一轮只在 `data/m2_tsundere_v2/` 生成傲娇候选和30条抽查，`prepare_data.py`、`scripts/m2.py` 仍读取 `data/m2/`、`configs/m2*.json` 和 `results/m2/`。因此用户从README打开的开发对照属于旧版，状态命令仍校验旧版冻结清单。

另一个实质问题是旧准备程序只取单轮用户问题和目标答案，不处理场景的 `history`；如果直接把多轮候选复制进去，会把触发角色反应的前文丢掉。

## 当前修复

M1的12条教学数据、训练配置、模型与Adapter属于已经验证的教学实验；保留它们的原内容。正式角色训练需要接入新的多轮编码函数，不能拿M1教学训练命令处理M2数据。

## 旧记录怎样保留

旧版完整保存到 `history/m2_persona_v1/`，包括配置、训练/开发/测试数据、各轮结果、冻结清单和原代码与文档。归档时核对原冻结清单中的核心文件及证据文件SHA-256，均匹配。没有把旧结果改名冒充新结果。

`data/m2_tsundere_v2/` 是首次候选快照，仍保留当时状态；README明确它不是当前主入口。旧生成脚本 `create_m2_seed.py` 已停用，避免重新写回旧数据。

v2第一轮结果现在保存在 `history/m2_tsundere_v2/results/m2/development_round1/`。加入“暂定决策不能冻结”的保护后又实际运行相同生成条件，当时v2有效结果已随完整准备包归档；v2两轮27条回答文本一致。当前主目录的 `results/m2/prompt_probe.json` 是按v3重新实际生成的27条输出。没有手改回答，追加保护并不证明质量有进步。

## 验证结果与剩余问题

结构检查：360条训练实例／120族／120种目标答案，300条单轮、60条带前文；开发24题、测试60题。当前v3最长训练152 token，推理输入最长676 token，低于256/768的各自上限。

当前23项测试通过，覆盖完整前文保留、只监督最后回复、同一句问题在不同前文下不被误删、跨集合相同上下文拒绝、旧版开发记录拒绝、输出缺失/重复拒绝，以及暂定Prompt不能冻结。

27条新输出均正常结束，使用同一Qwen2.5-1.5B-Instruct、MPS、bfloat16、贪心解码；没有加载M1 Adapter，没有正式训练，也没有生成最终测试答案。

工程混用已修复，但当前原模型的角色感仍不足，技术题和关系边界仍有失败。详见 [真实对照](../results/m2/prompt_comparison.md) 和 [本轮选择说明](../results/m2/prompt_decision.md)。这些普通口吻和错误是新版Prompt下的真实输出，不是旧版遗留，更不是LoRA效果。

当前v3准备包已冻结。用户原意见18pass/12revise已归档；12条及同类38个场景的修订现已落实，原通过回复保留，用户随后明确确认当前30条全部pass，原意见和实施记录保留；见 [人工抽查反馈](M2_人工抽查反馈.md)。剩余是模型效果与数据审核工作，不应把版本同步的完成当成角色效果达标。

学习/技术修订实施记录见 [12条前后对照](../results/m2/revised_12_samples.md)。当前配置、角色卡、评分、数据、审核表、教程与开发输出统一使用v3。
