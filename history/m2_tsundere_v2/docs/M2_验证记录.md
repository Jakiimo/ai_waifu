# M2 傲娇 v2 验证记录

日期：2026年10月13日。当前版本 `m2-tsundere-v2`；角色凛音；评分规则 `tsundere-v2`。旧版原记录已归档，当前文件只描述新版。

## 实际完成

- 主配置、训练数据、开发/测试标准、提示词、评分规则与教程已同步。
- 数据整理：120个场景族展开成360条实例，120个不同目标答案；300条单轮、60条多轮前文。
- 开发24个场景，最终测试60个场景。训练/开发/测试场景族无交叉，完整上下文无完全重复，字符近重复检查未超过0.65阈值；不是语义泄漏证明。
- 真实Qwen Tokenizer验证：训练最长144 token，最大允许256；推理输入最长457，最大允许768。前文和padding不参与loss，最后回复和结束符参与。
- 原模型实际生成固定9个开发场景×3种Prompt共27个回答；全部以EOS结束，没有触及256个新token上限。
- 回归检查20项通过：M1标签边界、M2重复/隔离保护、多轮编码、过期记录拒绝、暂定决策不可冻结。
- `scripts/m2.py status` 显示当前版本、360/24/60及27条匹配证据；M1状态仍是已验证。

## 实验条件

基础模型Qwen/Qwen2.5-1.5B-Instruct，版本 `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`。设备MPS，基础权重bfloat16，torch2.8.0、transformers4.57.6，贪心解码 `do_sample=false`，最大新token256。与M1共享同一基础权重，本轮不加载Adapter。

short是简短角色指令，strong_profile是详细设定，strong_examples再附加两个训练区对话示例。开发参考答案不输入模型，最终测试题不参与Prompt选择。与旧版不同，三种Prompt都不附加旧版技术知识背景，不能将新旧回答当作同条件质量变化。

输入指纹、完整消息、回答、token数、结束原因和每条耗时保存在 [prompt_probe.json](../results/m2/prompt_probe.json)。阅读版是 [开发集对照](../results/m2/prompt_comparison.md)。加入冻结保护前的一轮另行保留，最终记录与当前关键代码指纹匹配。

## 没有完成的部分

27条是小规模开发检查，不是完整24题全量评测。原模型被夸时角色反差不足，倾听要求没有正确接住，labels=-100和端口仍有错误，个别回复施加关系压力。当前strong_examples只是暂定候选，未证明更好，`ready_to_freeze=false`。

最新30条训练台词抽查意见已记录为30/30：18条pass、12条revise，后者需要更俏皮、有姐姐感。台词修订尚未落实，全量人工审核未完成。新版工程包尚未冻结，M3正式角色训练、M4聊天Demo、M5独立最终评测未运行，不存在傲娇Adapter或质量提升结论。

版本混用的原因及修复范围见 [一致性排查](M2_一致性排查.md)。操作与原理见 [M2入门教程](M2_入门教程.md)。
