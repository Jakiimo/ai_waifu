# M2 数据说明

版本：m2-persona-v1  
目标：俏皮、偏二次元的中文表达，同时保持回答有帮助、技术内容准确。

## 来源与生成方式

本项目的种子数据由当前开发助手 AI 辅助撰写，没有下载第三方对话语料，也没有使用真人私人聊天记录。原始内容保存在 `raw_cards.jsonl`，可复现的写入脚本为 `scripts/create_m2_seed.py`。

这不是经过多人标注的公开高质量数据集。作者 AI 自检、格式检查和 Tokenizer 验证已执行，用户的人工风格抽查尚未完成，不得把它写成已人工审核的真实用户数据。对外发布的许可证尚未单独选定，不将第三方库或模型许可证自动套用到这套数据上。

## 规模与独立性

| 集合 | 数量 | 用途 |
|---|---:|---|
| 训练集 | 300 条，100 个场景族，100 个不同目标回答 | M3 更新 LoRA 参数 |
| 开发集 | 20 个独立场景，5 类各 4 个 | 选择 Prompt 与后续训练配置 |
| 测试集 | 50 个独立场景，5 类各 10 个 | M5 最终评测 |

训练集每个场景有 3 种问法，共享同一个目标回答。这是输入表达增强，不是 300 个独立问题或回答。训练类别为日常、普通情绪表达、学习与技术问答，每类 75 条、25 个场景族。

开发和测试另行编写，没有把训练问法随机分到其他集合。场景族交叉、标准化后的完全重复以及字符近重复均检查。相近主题可以出现在不同集合中；自动检查无法证明语义完全独立。

## 格式与标签

`train.jsonl` 每行包含：

```json
{
  "id": "train-daily-01-v1",
  "family_id": "train-daily-01",
  "category": "daily",
  "source": "project_authored_ai_assisted",
  "review": "ai_author_checked_human_pending",
  "messages": [
    {"role": "user", "content": "今天把房间收拾干净了。"},
    {"role": "assistant", "content": "生活地图刷新成功！趁现在拍张照片留个纪念，再挑一个最容易保持的小区域，整洁就更容易续航啦。"}
  ]
}
```

训练时会加入固定的 short system prompt，应用 Qwen 聊天模板，只有目标回答与结束标记参与 loss。M2 使用真实 Tokenizer 验证长度和标签，但没有更新参数或生成新 Adapter。

开发集中的 `reference_answer` 与测试集中的 `expectation` 用于检查结果；它们不是模型输入。M5 只能把 system prompt 与 `messages` 交给模型。

strong_v4 的 system prompt 公开包含两条领域背景定义，是开发集调试后的工程选择。它没有复制测试参考文本或使用测试输出，但会给 B/D 组额外的相关上下文；最终结论需说明这个配置差异，不能将 C/B 的全部效果差异归因于风格。

测试集含少量固定历史场景，用于观察话题切换和建议重复；它不是完整自由运行的多轮 benchmark。

## 清洗与限制

- 去除空内容、重复输入；相同输入出现冲突回答会直接失败。
- 同一场景族保留在同一集合；开发与测试输入不参与训练。
- 使用标准化字符三元组 Jaccard 相似度检测近重复，阈值为 0.65。这是实用筛查规则，不是理论上的泄漏界限。
- 输入超过长度限制时失败，拒绝悄悄截断目标回答。
- 共享回答未去重，否则会误删有意保留的不同问法；报告同时给出独立场景和回答数量。

合成数据有固定表达和作者偏好，可能让模型学到表面套路。100 个独立目标回答的覆盖仍很有限，不能据此承诺生产质量。后续改进应增加真实不同场景、重新审核目标回答，并创建新数据版本。

## 抽查与冻结

`results/m2/review_samples.csv` 是固定种子抽取的 30 条训练样本，`human_verdict` 初始为 pending。用户可以填写 pass/revise/reject 与备注；不伪造完成状态。

`frozen_manifest.json` 记录数据、Prompt 和评分规则的 SHA-256。冻结表示标准已确定，不表示数据已经完美或人工抽查已经完成。修改冻结内容需要新版本，不能使用旧版本的校验记录。
