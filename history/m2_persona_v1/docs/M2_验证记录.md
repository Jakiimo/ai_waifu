## 开发中发现的问题

最初的角色 Prompt 会让小模型把技术标签解释为情绪或数值目标，也会误读演示任务。CPU float32 对照仍有错误，不能只归因于 MPS。风格示例版本还有生硬照搬比喻的问题。

strong_v4 加入明确任务要求和公开的少量领域背景后，关键技术定义更接近正确，但仍有任务误读、细节不严谨及风格偏弱。它是当前可解释的工程基线，不是已证明的最佳方案。

C/B 的背景信息不同，不能把全部效果差异归因为角色 Prompt 压缩。D/B 的详细 Prompt 相同，仍能用于检查 Adapter 的额外贡献。

完整原始输出、选择理由和局限见 `results/m2/prompt_comparison.md` 与 `prompt_decision.json`。第一、二轮输出另行保存。三轮重复使用同一批五个开发场景，独立题目数不能累加成六十个。
