# M2 入门教程

本页记录旧版 M2 流程。当前角色目标已修订为嘴硬心软的傲娇型；最新内容从 [新台词抽查](../data/m2_tsundere_v2/review_samples.md) 与 [风格修订说明](Galgame_风格调研与修订.md) 开始阅读。旧冻结版暂不作为正式训练方案。

M1 证明你能运行和训练模型。M2 负责准备让它学的内容，以及判断效果的规则。本次目标由你选择为“更俏皮、偏二次元”，准确、有用仍然优先。

这一阶段不训练新 Adapter。先把教材、练习题和考试规则准备好，M3 才进行正式训练。

## 1 训练集 开发集 测试集分别做什么

| 集合 | 在项目里做什么 | 能不能影响参数或选择 |
|---|---|---|
| 训练集 | 给模型看问题与期望回答，计算 loss | M3 用它更新 LoRA 参数 |
| 开发集 | 试 Prompt、选择训练配置或 checkpoint | 可以据此调整方案，但不能当最终效果证明 |
| 测试集 | 方案固定后检查未参与选择的题目 | 不用它挑 Prompt、调参数或选模型 |

如果把同一个场景换三种说法，分别放到训练和测试里，模型可能是在回答学过的题。这里用 `family_id` 把同一个场景的三种问法绑在一起，全部留在训练区；开发与测试另外编写。

本次得到 300 条训练样本，但只有 100 个独立场景、100 个不同目标回答。数量不是越大越好，也不能把改写后的行数当成独立信息量。

## 2 你先看一条数据

进入项目目录：

```bash
cd "/Users/jakiimo/Desktop/AI Waifu"
```

打开 `data/m2/raw_cards.jsonl`，每行是一个场景，包括三种用户问法和一个目标回答。第一条目标回答会用“生活地图刷新成功”这样的轻度比喻；技术问题则先解释正确概念，不为了角色风格改错定义。

数据是本项目 AI 辅助撰写的合成示例，不是从现成数据集筛选出的真人对话。详细来源与局限见 [数据说明](../data/m2/DATA_CARD.md)。

`prepare_data.py` 会把场景展开成标准的 `messages` 对话，写入 `data/m2/train.jsonl`。之后 M3 可以直接消费这份文件。

## 3 复跑数据检查

```bash
.venv/bin/python prepare_data.py
```

第一次准备会执行以下检查；本次实验已经完成准备并冻结，复跑默认核对文件，不覆盖：

1. 样本内容不为空，id 与场景族有效。
2. 相同输入不会重复训练；相同输入的矛盾回答会失败。
3. 训练、开发、测试没有场景族或标准化输入交叉。
4. 字符近重复没有达到预设筛查阈值。
5. 用真实 Qwen Tokenizer 确认训练长度、回答标签和结束符。
6. 用各候选 Prompt 检查开发/测试输入长度，但不生成测试回答。

完整结果在 `results/m2/data_report.json`。检查长度可以读测试输入，不代表允许根据测试结果调参；本阶段没有生成测试输出。

现在短训练样本仍补齐到 256 token，最大输入限制是 512 token，生成上限提高到 256 token。生成是否完整会单独记录为 `eos` 或 `length`，不会把中途截断悄悄算成正常结束。

## 4 看 Prompt 开发实验

打开 [开发集对照](../results/m2/prompt_comparison.md)。每类选一个开发场景，共五题，比较 short 和几个详细 Prompt。

四组最终实验会使用：

| 组别 | 模型 | Prompt |
|---|---|---|
| A | 原模型 | short |
| B | 原模型 | 选定的 strong Prompt |
| C | 新微调模型 | 与 A 相同的 short |
| D | 新微调模型 | 与 B 相同的 strong |

M2 只有原模型和候选 Prompt 的开发输出，还没有 C/D 的正式微调结果。最重要的最终比较是 D/B，因为它们只有 Adapter 的主要差异，不能故意削弱 B 来显示微调有效。

选定的详细 Prompt 不仅描述角色，还包含开发集暴露的问题所需的少量背景定义。背景在 `configs/m2_prompts.json` 中公开，不来自测试输出。因此 C/B 是两种完整配置的比较，不能把全部差异说成“人设提示词压缩”或“模型学到了新知识”；D/B 使用同一背景，更适合隔离 Adapter 的额外贡献。

你要观察：有没有回答真正的问题？是不是只是加口癖？技术解释是否正确？普通聊天是否太长？比喻是否贴合？先看内容，再看风格。

第一轮出现过技术解释错误和任务误读，保存在 `results/m2/prompt_comparison_round1.md`。CPU 对照也出现错误，说明不能仅将问题归因于 MPS；目前没有进一步证明误差的全部原因。

这也是为什么不能盲目认为长 Prompt 或更多二次元表达一定更好。选定版本与理由见 [Prompt 选择记录](../results/m2/prompt_decision.md)。

开发推理命令是：

```bash
.venv/bin/python scripts/m2.py dev-probe
```

当前版本已冻结，命令会阻止你覆盖开发记录。先阅读已有结果即可；若想自己试新 Prompt，应建立下一版本并保留旧记录，不直接改这套冻结文件。

## 5 人工抽查是你现在最值得做的一步

打开 `results/m2/review_samples.csv`，里面有 30 条随机抽取的训练样本。每条检查三件事：

1. 问题和回答能对得上吗？
2. 这种俏皮表达是你希望角色学到的吗？
3. 技术事实、建议和信息边界是否有明显问题？

`human_verdict` 可以填 pass、revise 或 reject，修改理由写在 notes。你也可以直接在聊天里引用样本 id，说哪句话希望调整；不用假装所有 AI 生成内容都已经通过人工审核。

如果要改训练内容，先建立新数据版本并更新冻结记录。只填写抽查表不会修改训练样本，也不会更新模型。

## 6 冻结是什么意思

冻结就是记录当前文件的指纹。SHA-256 将文件内容映射成一个摘要；文件变动时，校验会失败。

这不是把文件变成不能编辑，而是让实验知道“你现在使用的还是不是同一套题目、Prompt 和评分规则”。不然训练后悄悄改题目，结果就无法公平比较。

查看状态：

```bash
.venv/bin/python scripts/m2.py status
```

预期看到数据数量、选定的 strong Prompt，以及冻结校验通过。状态会明确提醒人工风格抽查尚未记录完成。

评分标准在 `configs/m2_rubric.json`：人设一致性和有用性各评 1–5 分，成对比较允许平局。句数、称呼和游戏词汇只是自动线索，不能代替人工质量判断。

## 7 本次新增文件

- `configs/m2.json`：数据版本、长度、开发题目与选定 Prompt。
- `configs/m2_prompts.json`：short 和详细候选提示词。
- `configs/m2_rubric.json`：先于最终测试设定的评分规则。
- `data/m2/raw_cards.jsonl`：100 个原始训练场景。
- `data/m2/train.jsonl`：300 条标准训练样本。
- `data/m2/dev_scenarios.jsonl`：20 个开发场景与参考回答。
- `data/test_scenarios.jsonl`：50 个测试场景与预先设定的检查要点。
- `data/m2/frozen_manifest.json`：冻结指纹与模型版本。
- `results/m2/`：清洗、抽查、Prompt 开发与选择记录。

M1 的文件和 Adapter 保持原样。`scripts/m1.py train` 仍然只训练 M1 的 12 条示例，不会自动改为 300 条；正式训练入口会在 M3 建立。

## 8 这一阶段你应当学会什么

能够解释训练、开发和测试的不同用途；知道同场景改写要放在一起；能阅读一条训练对话并检查目标回答；理解强 Prompt 基线和冻结的作用；能区分合成数据的行数、独立场景数与人工审核状态。

这些工作决定后续的微调与评测有没有意义，不只是训练前的格式转换。
